## 1. 概要

Issue #135 の対応。職務経歴書の本文（Markdown の貼り付け）を、会社・案件の詳細・文章項目の
項目別データに分割し、ポートフォリオアプリで管理する（設計は
[基本設計書 4.9](../02.design/DESIGN.md#49-職務経歴書データ) と
[基本設計書 6.3](../02.design/DESIGN.md#63-職務経歴書の生成) を参照）。

## 2. 変更内容

| 区分 | 内容 |
| ---- | ---- |
| DB | モデル `Company`（`companies`）・`SkillsheetText`（`skillsheet_texts`）を追加し、`Project` に会社と案件の詳細の列を追加する。旧 `Skillsheet`（`skillsheet`）を削除する（マイグレーション `0016_skillsheet_structured_data`） |
| アプリ | `portfolio/export.py` を、項目別データから Markdown を組み立てる方式に置き換える。会社画面・案件の詳細・文章項目の編集画面を追加し、本文の貼り付け画面を削除する |
| データ移行 | 既存の本文（Markdown）から項目別データへの移行は、リポジトリ外の使い捨てスクリプトで本番に 1 回だけ実行する。アプリの機能・管理コマンドにはしない |

## 3. 手順

### 3.1. ローカルでの動作確認

マージ前にローカルで確認する。

```bash
docker compose -f webapp/docker-compose.yml up -d db
```

1. `uv run python manage.py migrate` を実行し、`0016` まで適用できることを確認する
2. 3.2 の移行データを、3.3 の適用コードでローカルの DB へ適用する
3. 職務経歴書のプレビューと PDF が、移行元の本文と同等の内容であること、警告が 0 件であることを確認する
4. 「会社」「案件登録」の「職務経歴書の記載内容」「職務経歴書」の文章項目で、編集 → 確認 → 保存ができることを確認する

### 3.2. 移行データの作成

実データはリポジトリ・本書に記載しない。移行元は、ローカルに保管している職務経歴書の本文（Markdown）とする。

1. 本文を解析し、会社・案件の詳細・文章項目を JSON に出力するスクリプトを、リポジトリ外に作成する。解析規則は次のとおり
   - `氏名:` 行を氏名とする。`最終更新日:` 行は取り込まない
   - `■職務概要`・`■活かせる経験・得意分野`・`■自己PR` の本文を文章項目とする。末尾の `以上` は除く
   - `■職務経歴 概略`・`■テクニカルスキル`・`■保有資格` は生成するため取り込まない
   - `■開発経歴` 配下の `###` 見出しを本業（`main`）、`■副業` 配下を副業（`side`）の会社とする。見出しの
     会社名・部署・雇用形態・在籍期間と、会社概要（`【資本金】` 等）を取り込む
   - 案件見出し（`**期間｜案件名**（体制）`）と、`案件概要`・`業務内容`・`担当工程`・`環境・言語` の箇条書きを案件の詳細とする
2. JSON の内容を確認する。会社・案件の件数、雇用形態の判定（括弧書きが雇用形態でない見出し）、
   案件の対応付けを目視で確認する
3. 既存案件との対応付けは、案件名の一致で行う。案件名が異なる案件は識別子で固定して対応付け、
   対応がない見出しは案件として新規に作成する（使用スキルなし）。既存案件の案件名・期間は変更しない

### 3.3. 本番への移行データ適用

マージ・CD（`deploy-oci.sh` による `migrate`）の完了後に実施する。

1. 作業端末から OCI ホストへ SSH 接続する

   ```bash
   ssh oci-server
   ```

2. 3.2 の JSON を埋め込んだ適用コードを標準入力から `manage.py shell` へ流す。まず書き込みをロールバックする
   ドライランで件数を確認し、問題がなければ本実行する

   ```bash
   kubectl -n app-prod exec -i deploy/portfolio-web -c web -- python manage.py shell
   ```

   - 適用は 1 つのトランザクションで行い、`companies`・`skillsheet_texts` が空のときだけ書き込む
   - 実行内容の証跡を作業証跡ログに残す。ログには個人データを含めない（件数のみを記録する）
3. 管理画面「職務経歴書」で、警告が 0 件であること、プレビューと PDF の内容が移行元と同等であることを確認する
