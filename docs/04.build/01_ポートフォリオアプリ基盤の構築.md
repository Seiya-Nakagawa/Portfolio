## 1. 概要

Issue #47。[基本設計書](../02.design/DESIGN.md)に基づき、`webapp/` にポートフォリオアプリの基盤
（Django プロジェクト・実績 DB スキーマ・コンテナ定義）を構築する。infra-oci 上の既存アプリ
（kakeibo）と同じ構成（Python / Django・uv・Docker）を踏襲する。

## 2. 前提条件

- Python 3.14、uv、Docker が利用できること
- infra-oci 側で MySQL データベース `portfolio` が作成済みであること
  （[infra-oci Issue #127](https://github.com/Seiya-Nakagawa/infra-oci/issues/127)。
  ローカル検証では不要）
- OCI Vault に `portfolio-secret-key`・`portfolio-db-name`・`portfolio-db-user`・
  `portfolio-db-password` が登録済みであること（本番適用時のみ）

## 3. 手順

### 3.1. Django プロジェクトの作成

1. `webapp/` に `pyproject.toml` を作成する。`requires-python` は `>=3.14,<3.15`、依存は
   `django>=5.2.8,<5.3`・`django-environ`・`gunicorn`・`mysqlclient`・`whitenoise`、
   開発用に `ruff` とする。
2. `.python-version` に `3.14` を記載する。
3. 依存関係を解決し、`uv.lock` を生成する。

   ```bash
   uv lock
   ```

   - `pyproject.toml` から依存関係を解決し、バージョンを固定した `uv.lock` を生成する。

4. `config/`（Django プロジェクト）と `portfolio/`（アプリ）、`manage.py`、
   `templates/`、`static/` を配置する。`INSTALLED_APPS` に `portfolio` を登録する。

### 3.2. 設定ファイルの作成

`config/settings/` に以下の 4 ファイルを作成する。

| ファイル | 内容 |
| -------- | ---- |
| `base.py` | 共通設定。`SECRET_KEY` を環境変数から取得する。言語 `ja`、タイムゾーン `Asia/Tokyo`、静的ファイルは WhiteNoise で配信する |
| `development.py` | MySQL へ TCP（`DB_HOST`・`DB_PORT`）で接続する |
| `production.py` | MySQL へ UNIX ソケット（`DB_SOCKET_PATH`）で接続する。`FORCE_SCRIPT_NAME` の既定値を `/portfolio` とし、`STATIC_URL` にも同じプレフィックスを付ける |
| `test.py` | ユニットテスト用。SQLite（メモリ）に接続する |

DB 名・ユーザー・パスワードは、いずれも環境変数（`DB_NAME`・`DB_USER`・`DB_PASSWORD`）から取得し、
コードに直接記述しない。`.env.example` に変数名の一覧を記載する。

### 3.3. 実績 DB のモデルとマイグレーションの作成

1. `portfolio/models.py` に、`Level`・`Skill`・`Project`・`ProjectSkill`・`Certification`・`Work` を
   定義する。テーブル名は `levels`・`skills`・`projects`・`project_skills`・`certifications`・
   `works` とする（`db_table`）。`ProjectSkill` は `CompositePrimaryKey` で
   `project_id` + `skill_id` を主キーとする。
2. マイグレーションを生成する。

   ```bash
   SECRET_KEY=x uv run python manage.py makemigrations portfolio --settings=config.settings.test
   ```

   - モデル定義から `portfolio/migrations/0001_initial.py` を生成する。

### 3.4. levels 初期値の投入マイグレーションの作成

1. `portfolio/migrations/0002_insert_levels.py` を作成し、`RunPython` で `levels` に
   [基本設計書 4.6](../02.design/DESIGN.md#46-levels習熟度レベル定義)の 5 件（レベル 1〜5）を
   `update_or_create` で登録する。

### 3.5. 経験年数の算出ロジックとユニットテストの作成

1. `portfolio/experience.py` に、[基本設計書 4.9](../02.design/DESIGN.md#49-経験年数の算出)の
   算出ロジックを DB に依存しない関数として実装する。
   - `expand_months`: 開始年月〜終了年月（空の場合は基準日）を通し月番号の集合に展開する
   - `aggregate_skill_experience`: スキルごとに使用案件の展開月を和集合し、ユニーク月数と開始年を返す
   - `format_experience`: ユニーク月数を `Mヶ月` / `N年` / `N年Mヶ月` に変換する（0 は出力対象外）
2. `portfolio/tests/test_experience.py`・`test_models.py` にユニットテストを作成する。
3. テスト・静的解析を実行する。

   ```bash
   SECRET_KEY=x uv run python manage.py test --settings=config.settings.test
   uv run ruff check .
   uv run ruff format --check .
   ```

   - 1 行目: ユニットテストを実行する。
   - 2 行目: 静的解析を実行する。
   - 3 行目: フォーマットの差異がないことを確認する。

### 3.6. コンテナ定義の作成

1. `webapp/Dockerfile` を作成する。ビルド用ステージで `uv sync --locked --no-dev` により依存を
   導入し、実行用ステージへ成果物をコピーして `collectstatic` を実行、`gunicorn` で起動する。
2. `.dockerignore`、ローカル開発用の `docker-compose.yml`（MySQL 8.0 + アプリ）を作成する。
3. リポジトリ直下の `.gitignore` に `webapp/.env` 等のローカル生成物を追加する。

### 3.7. OCI Vault からの接続情報同期の定義

1. `k8s/vault-sync.yaml` に ExternalSecret を定義する。infra-oci 側の ClusterSecretStore
   （`oci-vault`）を参照し、Vault 上の `portfolio-*` を Kubernetes Secret `portfolio-secrets` の
   `SECRET_KEY`・`DB_NAME`・`DB_USER`・`DB_PASSWORD` へ同期する。

### 3.8. 動作確認

1. コンテナイメージをビルドする。

   ```bash
   docker build -t portfolio-webapp webapp
   ```

   - `webapp/` の Dockerfile からイメージをビルドし、依存導入と `collectstatic` が成功することを確認する。

2. 使い捨ての MySQL 8.0 コンテナを起動し、同一ネットワークからマイグレーションを実行する。

   ```bash
   docker network create pf-test
   docker run -d --rm --name pf-mysql --network pf-test \
     -e MYSQL_ROOT_PASSWORD=<任意> -e MYSQL_DATABASE=portfolio \
     -e MYSQL_USER=<任意> -e MYSQL_PASSWORD=<任意> mysql:8.0
   ```

   - 検証用ネットワークを作成する。
   - 検証用の MySQL を起動する（パスワードは検証用の使い捨て値を指定し、記録しない）。

3. MySQL の起動完了後、アプリのコンテナでマイグレーションを適用する。

   ```bash
   docker run --rm --network pf-test \
     -e DJANGO_SETTINGS_MODULE=config.settings.development -e SECRET_KEY=<任意> \
     -e DB_NAME=portfolio -e DB_USER=<任意> -e DB_PASSWORD=<任意> -e DB_HOST=pf-mysql \
     portfolio-webapp python manage.py migrate
   ```

   - `0001_initial`・`0002_insert_levels` が適用され、`levels` に 1〜5 が登録されることを確認する。

4. 検証用のコンテナとネットワークを削除する。

   ```bash
   docker stop pf-mysql
   docker network rm pf-test
   ```

   - 検証用 MySQL を停止する（`--rm` のためコンテナも削除される）。
   - 検証用ネットワークを削除する。
