## 1. 概要

Issue #173 の対応。公開ページ・ログイン・PDF 生成・画像アップロードの流量制限、画像の内容による形式判定と
1 ユーザー 50MB の容量上限、不要になった画像の削除を実装する。設計は
[基本設計書 5.3.2](../02.design/DESIGN.md#532-スキル実績管理ポートフォリオアプリ)・
[7.3](../02.design/DESIGN.md#73-流量制限) を参照する。

## 2. 前提条件

- アカウント画面とユーザー別の画像の保存先（構築手順書 19・23）が適用済みであること

## 3. 手順

### 3.1. 流量制限

1. `RateLimitCounter` モデル（`rate_limit_counters`）とマイグレーション `0024` を追加する。
   対象・識別子（ハッシュ）・区間の開始で一意とし、回数を保持する
2. `webapp/portfolio/ratelimit.py` に、回数の計数（`hit`）・接続元 IP の取得（`client_ip`）・期限切れの削除を実装する。
   `X-Forwarded-For` は末尾から `TRUSTED_PROXY_COUNT` 番目の値のみを用いる
3. `RateLimitMiddleware` で、接続元ごとの対象（`/u/`・`/media/`、`/login/`・`/accounts/`・`/admin/login/`）を制限する
4. ユーザーごとの対象（PDF 生成・画像アップロード）は `manage_views.py` で数え、超過時は例外 `TooManyRequests` を
   429 で返す
5. 上限値は `config/settings/base.py` の `RATE_LIMITS` に定義する

### 3.2. 画像の形式判定と容量上限

`webapp/portfolio/uploads.py` で、ファイルの先頭のバイト列から png・jpg・gif・webp を判定し、判定した形式の拡張子で保存する。
1 ファイル 5MB（`MAX_IMAGE_BYTES`）、1 ユーザーの保存済み画像の合計 50MB（`MAX_USER_IMAGE_BYTES`）を超える場合はエラーとする。

### 3.3. 不要な画像の削除と日次の整理処理

1. `webapp/portfolio/media_files.py` に、参照されなくなった画像の削除と、未使用画像の一括削除を実装する
2. 実績の削除・画像の差し替え時に、どの実績からも参照されなくなった画像を削除する（`registry.py`）
3. 管理コマンド `daily_maintenance` を追加し、期限切れの流量制限の回数と、アップロードから 24 時間を過ぎても
   実績に保存されていない画像を削除する
4. `k8s/cronjob.yaml` に毎日 03:00（日本時間）の CronJob を追加し、`deploy-oci.sh` の適用対象に加える

### 3.4. ローカルでの動作確認

```bash
uv run python manage.py test --settings=config.settings.test
uv run python manage.py daily_maintenance
```

`portfolio.tests.test_limits` で、各対象の流量制限・接続元 IP の取得・形式判定・容量上限・画像の削除を確認している。

### 3.5. 本番への適用

1. `k8s/configmap.yaml` に `TRUSTED_PROXY_COUNT: "1"` を追加済みである。共有 Ingress が `X-Forwarded-For` を
   付与することを、infra-oci 側の設定で確認する
2. マージ後の CD で、マイグレーションと CronJob の作成が行われる。完了後に次を確認する
   - `kubectl get cronjob -n app-prod` に `portfolio-daily-maintenance` があること
   - `kubectl create job --from=cronjob/portfolio-daily-maintenance maint-check -n app-prod` で手動実行し、
     ログに「整理しました」が出力されること（確認後に `kubectl delete job maint-check -n app-prod` で削除する）
