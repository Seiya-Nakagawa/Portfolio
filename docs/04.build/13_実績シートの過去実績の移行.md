## 1. 概要

Issue #59。旧 GAS の実績シート（Google スプレッドシート）に蓄積したスキル項目マスタ・案件・
使用実績を、本番の実績 DB へ移行する。実データは個人の職歴を含み、リポジトリが公開のため
コミットしない。移行用の管理コマンドのみをリポジトリに置き、CSV は実行時に渡す。

## 2. 前提条件

- [11 構築手順書](11_KubernetesマニフェストとデプロイスクリプトのOCI適用.md)が完了し、
  本番のポートフォリオアプリが稼働していること
- 移行コマンドを含むイメージがデプロイ済みであること
- 実績 DB の `skills`・`projects`・`project_skills` が空であること（空でない場合、
  コマンドは何も変更しない）

## 3. 手順

### 3.1. 移行コマンドの作成

`webapp/portfolio/management/commands/import_skill_sheet.py` を作成する。

- 指定ディレクトリの `skills.csv`・`projects.csv`・`project_skills.csv` を読み込む。
- 入力値はモデルの検証（形式・レベルの存在・年月の形式）と、案件・スキル項目の参照整合性・
  使用実績の重複で検証する。1 件でも不正があれば何も登録せずエラーで終了する。
- スキル項目の `sort_order` は、`skills.csv` の行順で 1 から通し番号を振る。
- 登録は 1 つのトランザクションで行う。
- スキル項目・案件・使用実績のいずれかに既存データがある場合は、何も変更しない。

### 3.2. 実績シートの CSV 書き出し

実績シートの以下の 3 シートを、UTF-8 の CSV として書き出す。CSV はリポジトリの外に置き、
コミットしない。

| ファイル | 必須列 |
| -------- | ------ |
| `skills.csv` | `skill_id`, `category`, `name`, `level`（`remarks` は任意） |
| `projects.csv` | `project_id`, `name`, `start_year_month`, `end_year_month` |
| `project_skills.csv` | `project_id`, `skill_id`, `version` |

- 上記以外の列（`sort_order` 等）は無視される。
- スキル項目の並びは、`skills.csv` の行順をそのまま引き継ぐ。カテゴリ間の順序とカテゴリ内の順序を
  1 から始まる通し番号の `sort_order` として登録する（実績シートの `sort_order` はカテゴリごとに
  振り直されており、カテゴリ間の順序を表せないため）。
- `levels` シートは、マイグレーションで投入済みのため書き出さない。

### 3.3. ローカルでの試行

ローカルの空の DB に対して実行し、件数と出力内容を確認する。

```bash
uv run python manage.py migrate
uv run python manage.py import_skill_sheet /path/to/csv
```

- マイグレーションで空の DB を用意する。
- CSV のディレクトリを指定して移行し、スキル項目・案件・使用実績の件数が表示されることを確認する。

### 3.4. 本番への移行

CSV を OCI ホスト経由で Pod へ渡し、移行後に削除する。

```bash
scp /path/to/csv/*.csv seiya@{OCI ホスト}:/tmp/
kubectl cp /tmp/skills.csv app-prod/{Pod 名}:/tmp/skills.csv -c web
kubectl cp /tmp/projects.csv app-prod/{Pod 名}:/tmp/projects.csv -c web
kubectl cp /tmp/project_skills.csv app-prod/{Pod 名}:/tmp/project_skills.csv -c web
kubectl exec -n app-prod {Pod 名} -c web -- python manage.py import_skill_sheet /tmp
```

- CSV を OCI ホストへ転送する（以降の `kubectl` は OCI ホスト上で実行する）。
- CSV を Pod の `/tmp` へコピーする。
- 移行コマンドを実行する。

移行後、Pod とホストの CSV を削除する。

```bash
kubectl exec -n app-prod {Pod 名} -c web -- rm /tmp/skills.csv /tmp/projects.csv /tmp/project_skills.csv
rm /tmp/skills.csv /tmp/projects.csv /tmp/project_skills.csv
```

- Pod 上の CSV を削除する。
- ホスト上の CSV を削除する。

### 3.5. 移行結果の確認

1. 公開 API `/portfolio/api/skills` が、使用実績のあるスキル項目を返すことを確認する。
2. 登録画面のスキル項目管理に、移行したスキル項目と経験年数が表示されることを確認する。
3. 登録画面のエクスポートで、警告（レベル未定義のスキル項目）が出ないこと、
   案件期間の行が職務経歴書マスタの案件名と一致することを確認する。
