## 1. 概要

Issue #165 の対応。共通マスタを除く全テーブルに所有者（`owner_id`）を追加し、既存データを運営者のユーザーに
紐づける。管理画面の全 API・集計・職務経歴書の生成を、ログインしたユーザーのデータに限定する。
設計は [基本設計書 4.1](../02.design/DESIGN.md#41-共通方針)・
[4.2](../02.design/DESIGN.md#42-テーブル構成)・[4.13](../02.design/DESIGN.md#413-テナント分離)・
[4.15](../02.design/DESIGN.md#415-既存データの移行) を参照する。

マイグレーションは次の 3 つに分けて適用する。

| マイグレーション | 内容 |
| ---------------- | ---- |
| `0021_owner_columns` | `user_profiles`・`usage_daily` を作成する。各テーブルに空を許す `owner_id` を追加する。`site_info` の主キーを自動採番へ、`skillsheet_texts` の主キーを自動採番の `skillsheet_text_id` へ変更し、`owner_id` と `text_key` の組み合わせを一意にする。`projects.company_id`・`project_skills.skill_id` の削除時の動作を保護から制限へ変更する |
| `0022_assign_owner` | 既存の唯一のユーザー（運営者）を所有者として、既存の行の `owner_id` を設定する。運営者を `is_staff` とし、プロフィール（公開）を作成し、パスワードを使用不可にする。ユーザーが 1 人でない場合は移行を中止する。スキル項目は共通マスタとして所有者を空のままにする |
| `0023_owner_required` | 共通マスタを持つ `skills` を除く各テーブルの `owner_id` を必須にする |

## 2. 前提条件

- 実績 DB（MySQL 8.0）に、ユーザーがちょうど 1 人（運営者）登録されていること
- ローカルの確認には Docker が使えること

## 3. 手順

### 3.1. ローカルでのマイグレーションの確認

使い捨ての MySQL コンテナで、マイグレーションとテストを実行する。

```bash
docker run --rm -d --name portfolio-mysql-check -e MYSQL_ROOT_PASSWORD={任意のパスワード} -e MYSQL_DATABASE=portfolio -p 127.0.0.1:3307:3306 mysql:8.0 --character-set-server=utf8mb4 --collation-server=utf8mb4_0900_ai_ci
```

- 確認用の MySQL 8.0 を、確認後に自動で削除される設定（`--rm`）でバックグラウンド起動する。ポートは 3307 に割り当てる

```bash
uv run python manage.py migrate
```

- 接続先を上記のコンテナに向けた設定で、`0023` までのマイグレーションを適用する

```bash
SECRET_KEY=test uv run python manage.py test --settings={上記のコンテナに接続するテスト用設定}
```

- 所有者の移行（`portfolio.tests.test_owner_migration`）とテナント分離（`portfolio.tests.test_tenant_isolation`）を含む全テストを MySQL 上で実行する

```bash
docker stop portfolio-mysql-check
```

- 確認用のコンテナを停止して削除する

### 3.2. 本番への適用前の準備

1. 実績 DB のダンプを手動で取得して保管する。移行に失敗した場合は、このダンプから戻す
2. 運営者のユーザーが 1 人であることを確認する

   ```bash
   ssh oci-server
   ```

   ```bash
   kubectl -n app-prod exec deploy/portfolio-web -c web -- python manage.py shell -c "from django.contrib.auth import get_user_model; print(get_user_model().objects.count())"
   ```

   - 出力が `1` であること。`1` 以外の場合、`0022_assign_owner` は移行を中止する

### 3.3. 本番への適用

マージ後の CD（`deploy-oci.sh` による `migrate`）で `0021` 〜 `0023` が適用される。

### 3.4. 適用後の確認

1. `kubectl -n app-prod exec deploy/portfolio-web -c web -- python manage.py showmigrations portfolio` で、`0021` 〜 `0023` が適用済みであること
2. 公開ページ（`/portfolio/`）に、移行前と同じ内容が表示されること
3. 運営者のユーザーが `is_staff` で、プロフィール（公開）が作成され、パスワードでログインできない状態であること
4. 既存の案件・会社・資格・実績・サイト情報・職務経歴書の文章項目の件数が、移行前と一致すること
