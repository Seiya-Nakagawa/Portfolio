## 1. 概要

Issue #169 の対応。管理画面にアカウント画面を追加し、ユーザー名の変更、公開設定の切替、外部アカウントの追加連携、
退会（全データと画像の削除）を実装する。設計は
[基本設計書 5.3.2](../02.design/DESIGN.md#532-スキル実績管理ポートフォリオアプリ) の「アカウント」と
[4.13](../02.design/DESIGN.md#413-テナント分離) を参照する。DB・マニフェストの変更はない。

## 2. 前提条件

- [20 構築手順書](20_外部アカウント認証とサインアップの実装.md) の外部アカウント認証が動作すること
- [21 構築手順書](21_OAuthクライアントの作成とOCI_Vaultへの登録.md) の開発用の OAuth クライアントを `.env` に設定済みであること

## 3. 手順

### 3.1. ローカルでの動作確認

```bash
docker compose -f webapp/docker-compose.yml up -d db
```

- 確認用の MySQL を起動する

```bash
uv run python manage.py runserver
```

1. 登録画面の「アカウント」で、ユーザー名を変更し、確認画面に URL が変わり旧 URL が無効になる旨が表示されることを確認する。変更後、旧 URL が 404 になること
2. 公開設定を切り替え、公開中は URL が表示されること。サイト情報の氏名が未入力の場合に警告が表示されること
3. 未連携の提供元の「連携する」で認可画面へ移動し、完了後に登録画面へ戻って「連携済み」になること
4. 連携が 1 つだけの間は「解除」が押せないこと。2 つ連携した状態で解除できること
5. 確認用のユーザーで、ユーザー名を誤って再入力すると退会できないこと。正しく入力すると退会でき、サービス紹介ページへ戻ること
6. 退会後、`MEDIA_ROOT/users/{ユーザーの id}/` が削除されていること。他のユーザーのデータと画像が残っていること

### 3.2. 適用後の確認

1. 運営者のアカウントで「アカウント」を開き、運営者のユーザー名を設定する
2. [22 構築手順書](22_ユーザー別の公開ポートフォリオと旧URLのリダイレクト.md) の 3.3 に従い、旧 URL の転送先を設定する
