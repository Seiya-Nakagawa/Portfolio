## 1. 概要

Issue #170 の対応。スキル項目を共通マスタと独自スキル項目に分け、ユーザーは独自スキル項目のみを追加・変更・削除できる
ようにする。種類の管理と共通マスタの編集は運営者のみとする。設計は
[基本設計書 4.3](../02.design/DESIGN.md#43-skillsスキル項目)・
[5.3.2](../02.design/DESIGN.md#532-スキル実績管理ポートフォリオアプリ) を参照する。DB・マニフェストの変更はない
（`skills.owner_id` は [19 構築手順書](19_データの所有者の追加と既存データの移行.md) で追加済み）。

## 2. 前提条件

- [19 構築手順書](19_データの所有者の追加と既存データの移行.md) のマイグレーションが適用済みであること
- 運営者のユーザーが `is_staff` であること

## 3. 手順

### 3.1. ローカルでの動作確認

```bash
docker compose -f webapp/docker-compose.yml up -d db
```

- 確認用の MySQL を起動する

```bash
uv run python manage.py runserver
```

1. 一般ユーザーでログインし、「スキル項目管理」で共通マスタに「編集」「削除」が表示されず、「区分」が「共通」であること
2. 「追加」で、種類を既存の種類から選び、`skill_id` の入力欄がないこと。保存した項目が「独自」で表示されること
3. 共通マスタと同じ種類・名前の項目を追加しようとするとエラーになること
4. 一般ユーザーのナビゲーションに「種類管理」が表示されないこと
5. 運営者でログインし、共通マスタの追加・編集と、「種類管理」の操作ができること

### 3.2. 適用後の確認

1. 運営者のアカウントで、共通マスタの件数が移行前と同じであること
2. 種データの取り込み（`import_skill_master`）の再実行で、独自スキル項目が変更されないこと
