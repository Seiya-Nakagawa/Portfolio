## 1. 概要

Issue #172 の対応。運営者専用の管理画面で、利用状況の集計値の確認とユーザーの利用停止・再開を行えるようにする。
設計は [基本設計書 5.1.4](../02.design/DESIGN.md#514-運営管理)・[5.3.4](../02.design/DESIGN.md#534-運営管理) を参照する。

## 2. 前提条件

- 認証とアカウント画面（構築手順書 20・23）が適用済みであること
- 運営者のユーザーに `is_staff` が設定されていること（マイグレーション 0022 で既存データから設定済み）

## 3. 手順

### 3.1. 管理サイトの構成

1. `webapp/portfolio/admin.py` に、運営者のみが使える管理サイト `OperatorAdminSite` を作成する
   - 権限は `is_staff` かつ有効なユーザーで判定する
   - トップページに、登録・公開中・利用停止中のユーザー数と、`usage_daily` の直近 30 日の日次推移を表示する
     （テンプレートは `webapp/templates/admin/usage_index.html`）
2. 同ファイルに、ユーザーの一覧 `UserAdmin` を作成する
   - 追加・変更・削除の権限は与えず、一括削除の操作も外す
   - 操作は「利用停止」「再開」のみとし、自分自身は停止の対象外にする
3. `webapp/portfolio/admin_apps.py` に `OperatorAdminConfig`（`SimpleAdminConfig` を継承）を作成する
   - 既定の管理サイトは全アプリの管理設定を自動登録するため、認証・外部アカウントのテーブルまで表示される。
     自動登録を行わず、`portfolio.admin` のみを読み込む
4. `webapp/config/settings/base.py` の `INSTALLED_APPS` で、`django.contrib.admin` を
   `portfolio.admin_apps.OperatorAdminConfig` に置き換える

### 3.2. 生成回数の集計

`webapp/portfolio/manage_views.py` の職務経歴書の PDF・Markdown のダウンロード処理で、生成に成功した後に
`usage.increment()` で `usage_daily` に加算する。

### 3.3. ローカルでの動作確認

```bash
uv run python manage.py test --settings=config.settings.test
```

`portfolio.tests.test_operator_admin` で次を確認している。

- 運営者以外・未ログインは入れない
- 管理サイトに登録されているのはユーザーのみで、案件・会社のデータは表示されない
- 利用停止・再開ができ、停止したユーザーはログインできない。自分自身は停止できない
- 追加・変更・削除はできない（403）
- 一覧のクエリ数がユーザー数に比例しない
- 職務経歴書の Markdown の生成回数が加算される

### 3.4. 本番への適用

マイグレーションと設定の追加はない。マージ後の CD の完了後、運営者でログインして `/admin/` に
利用状況とユーザー一覧が表示されることを確認する。
