# 要件定義書 - Portfolio（職務経歴書作成・ポートフォリオ公開サービス）

## 1. プロジェクト概要

### 1.1. 目的

- エンジニア（SES・フリーランス・転職活動中の会社員等）が、案件ごとの使用実績（期間・使用スキル）を
  登録するだけで経験年数が自動で算出され、職務経歴書を最新の内容で取得できるサービスを提供する
- 登録した内容から、ユーザーごとの公開ポートフォリオを提供する。経験年数は職務経歴書と公開ポートフォリオの
  双方へ同一の値を供給し、手入力による二重管理をなくす
- 個人開発のサービスとして一般に公開し、収益化する
- 運営者（本人）も一利用者として本サービスを利用し、本人のポートフォリオ・職務経歴書を本サービスで管理する

### 1.2. 背景

| 項目 | 内容 |
| ---- | ---- |
| プロジェクト名 | Portfolio（職務経歴書作成・ポートフォリオ公開サービス） |
| 公開 URL | `technohonesty.com` のサブドメイン。<mark>サブドメイン名は未確定（[Issue #160](https://github.com/Seiya-Nakagawa/Portfolio/issues/160)）</mark> |
| ホスティング | OCI 基盤（infra-oci リポジトリ管理） |

- 職務経歴書の経験年数を手入力で管理すると、実際に使用した期間と一致せず、案件のたびに更新の手間が
  発生する。この課題は SES・フリーランスのエンジニアに共通する
- 本アプリは本人専用のポートフォリオサイト兼スキル実績管理として、案件単位の使用実績からの経験年数の
  算出と、職務経歴書 PDF の自動生成を実現している。これを本人以外も利用できるようにすることで、
  同じ課題を持つエンジニアへ提供できる

### 1.3. 方針

- 既存のポートフォリオアプリをマルチユーザー対応し、商用サービスとする。別のシステムは新設しない
- 主たる提供価値は職務経歴書の作成とする。公開ポートフォリオは付加機能と位置付ける
- 誰でもサインアップして利用できる。認証は外部アカウント（Google・GitHub）で行い、本サービスで
  パスワードを保持しない
- ユーザーのデータは互いに分離し、本人以外は参照・変更できない。公開ポートフォリオは、ユーザー本人が
  公開を選んだ場合に限り第三者が閲覧できる
- 運営者（本人）の既存データは、本サービスのユーザーの一人として移行し、本人のポートフォリオの公開を継続する
- 当初は全機能を無料で提供し、有料機能は後から追加する。<mark>料金体系・有料機能は未確定（[Issue #161](https://github.com/Seiya-Nakagawa/Portfolio/issues/161)）</mark>
- 経験年数の入力口を案件単位の使用実績登録に一本化し、公開ポートフォリオ・職務経歴書の双方へ供給する
- 職務経歴書 PDF は、取得時点の実績 DB の内容から組み立てて生成する
- スキル項目は、運営者が管理する共通マスタを全ユーザーで共有する。共通マスタにない項目は、
  ユーザーが独自に追加できる
- 公開ポートフォリオの表示部分（HTML/CSS/JavaScript）は、ビルドプロセス・外部フレームワークへの
  依存を持たない Vanilla 構成を維持する
- 表示言語は日本語に固定する（多言語対応は行わない）
- 配色・見た目はダークモード基調に固定する（テーマ切替機能は持たない）
- 無料提供の期間は既存の単一環境で運用する。可用性は有料機能の提供開始時に見直す

## 2. 対象範囲

### 2.1. スコープ内

サービス共通。

- サービス紹介ページ（サインアップへの導線を含む）
- 外部アカウント（Google・GitHub）によるサインアップ・ログイン
- アカウント管理（ユーザー名の設定、公開設定、退会）
- 利用規約・プライバシーポリシーの掲示と、サインアップ時の同意取得
- 運営者による利用状況の把握、共通マスタの管理、規約違反ユーザーの利用停止

スキル実績管理（ユーザーごと）。

- 案件単位の使用実績（期間・使用スキル）の登録
- 独自スキル項目の登録・変更
- 資格（Certifications）・実績（Works）の登録・変更
- 経験年数の自動算出
- 職務経歴書データ（会社・案件の詳細・文章項目）の登録・変更
- 職務経歴書 PDF の生成（実績 DB の内容から組み立てる）

公開ポートフォリオ（ユーザーごと）。

- Hero / About / Skills / Certifications / Works / Contact の各セクション表示
- 公開・非公開の切替
- レスポンシブ対応（モバイル / タブレット / デスクトップ）

### 2.2. スコープ外

- OCI 基盤自体の新規構築・運用（infra-oci リポジトリの責務とする）
- 決済・課金機能（有料機能の提供開始時に別途要件化する）
- メールアドレス・パスワードによる認証
- 法人（エージェント企業・SES 企業）向けの機能（複数ユーザーの一括管理等）
- ユーザーごとの独自ドメインでの公開ポートフォリオ提供
- サービス内でのお問い合わせフォーム処理（Google フォームへ誘導するのみとする）
- 多言語表示、テーマ（ダーク / ライト）切替
- 高可用性の確保（6.1 節参照）

### 2.3. 現行機能との差分

| 項目 | 現行 | 変更後 |
| ---- | ---- | ------ |
| 利用者 | 本人 1 名 | サインアップした任意のユーザー |
| 認証 | 本人限定のログイン | Google・GitHub アカウントによるサインアップ・ログイン |
| データの所有 | 単一の利用者を前提とする | ユーザーごとに分離する |
| ポートフォリオサイト | 本人のサイト 1 つ | ユーザーごとの公開ポートフォリオ（公開・非公開を選択できる） |
| スキル項目 | 単一の利用者が管理する | 運営者が管理する共通マスタと、ユーザーごとの独自スキル項目 |
| 本人の既存データ | 単一の利用者のデータ | ユーザーの一人のデータとして移行する |
| 法的な掲示 | なし | 利用規約・プライバシーポリシーを掲示し、同意を取得する |
| 退会 | なし | ユーザーの全データを削除できる |
| 運営管理 | なし | 利用状況の把握・共通マスタの管理・利用停止 |

## 3. 用語定義

| 用語 | 定義 |
| ---- | ---- |
| 本サービス | 本要件定義書が対象とする、職務経歴書作成・ポートフォリオ公開サービス |
| ユーザー | 本サービスにサインアップした利用者 |
| 運営者 | 本サービスの運営者（本人）。運営者自身もユーザーとして本サービスを利用する |
| ユーザー名 | ユーザーがユーザー間で一意に設定する識別名。公開ポートフォリオの URL に用いる |
| 公開ポートフォリオ | ユーザーごとのポートフォリオページ。ユーザーが公開を選んだ場合のみ第三者が閲覧できる |
| スキル項目 | 経験年数の管理単位となる技術・製品。種類（カテゴリ）・名称を持つ |
| 共通マスタ | 運営者が管理し、全ユーザーが選択できるスキル項目 |
| 独自スキル項目 | ユーザーが独自に追加したスキル項目。追加したユーザーのみが選択・参照できる |
| 案件 | 業務の単位。開始年月・終了年月（継続中の場合は未設定）と、使用したスキル項目を保持する |
| 使用実績 | ある案件であるスキル項目を使用したという記録 |
| ユニーク月数 | 案件の開始年月から終了年月（継続中の場合は出力時点の年月）までを年月に展開し、スキル項目ごとに重複を除いて数えた年月の件数 |
| 経験年数 | ユニーク月数を N年Mヶ月 に換算した値 |
| ポートフォリオアプリ | 本サービスを提供する、OCI 基盤上のウェブアプリケーション |
| 実績 DB | ポートフォリオアプリが読み書きするデータベース。OCI 基盤（infra-oci リポジトリ管理）上に配置する |
| 会社 | 職務経歴書に記載する所属先・副業の契約先。本業・副業の区分と在籍期間を持ち、案件が所属する |
| 職務経歴書データ | 職務経歴書の記載内容のうち、スキル実績・資格以外の部分。会社、案件の詳細（体制・案件概要・業務内容・担当工程・環境）、文章項目（氏名・職務概要・活かせる経験・得意分野・自己PR）からなり、項目ごとに実績 DB に保持する |
| 直近案件 | 終了年月が未設定（継続中）の案件。存在しない場合は、終了年月が最も新しい案件 |

| 案件 | 実績 DB | 案件名、開始年月、終了年月（継続中の場合は未設定）、使用したスキル項目、所属する会社、職務経歴書に記載する詳細（体制・案件概要・業務内容・担当工程・環境） |
| 資格 | 実績 DB | 資格名、取得日、発行団体 |

| 職務経歴書の文章項目 | 実績 DB | 氏名、職務概要、活かせる経験・得意分野、自己PR。最新版のみを保持する |
| サイト情報 | 実績 DB | 氏名、肩書き、キャッチコピー、自己紹介文、生年月日、職業、学歴、居住地、趣味、GitHub URL、Contact の案内文・フォーム URL、著作権開始年 |

### 5.1. データに関する業務ルール

- 共通マスタを除くすべてのデータは、いずれか 1 人のユーザーに属する
- ユーザー名はユーザー間で一意とする
- 退会したユーザーのデータは即時に削除する。バックアップに残るデータは、バックアップの保持期間の経過をもって
  消去される
- 使用実績の登録単位は案件とする
- 同一期間に複数の案件を並行登録できる（本業と副業を並行する場合を想定する）
- 経験年数は、案件の開始年月〜終了年月（継続中の場合は出力時点の年月）を年月に展開したうえでの
  ユニーク月数の積み上げで算出し、N年Mヶ月 の形式で表示する。同一年月に複数の案件で同一の
  スキル項目を使用した場合も 1ヶ月として数える
- 案件の期間（開始年月・終了年月）は案件自体が保持する
- 登録画面の初期値は直近案件の登録内容（期間・使用スキル）とする。案件が1件も登録されていない
  場合は未選択とする
- 直近案件の使用スキルは、区切り（終了年月の確定）を待たずに随時更新してよい
- 案件名・案件期間は、経験年数の算出と職務経歴書の記載で同じ値を用い、別々に管理しない。
  職務経歴書に記載する案件の詳細は案件に、会社情報は会社に保持する
- 職務経歴書の各項目は実績 DB の該当データから組み立て、生成した職務経歴書を手作業で編集しない。
  `■テクニカルスキル` 表は案件実績・スキル項目から、`■保有資格` は資格から生成し、
  公開ポートフォリオと同じ値を用いる
- 公開ポートフォリオに表示するデータには案件・会社・職務経歴書データを含めない。公開対象はスキル項目・
  経験年数・資格・実績・サイト情報に限る
- 職務経歴書データは、個人情報および NDA 相当の案件情報を含むため、本リポジトリでは一切管理しない。
  実績 DB にのみ保持し、所有するユーザーのログインを要する画面からのみ参照・編集できるものとする
- 職務経歴書データは最新版のみを保持し、変更履歴は持たない
- 共通マスタのスキル項目の名称を変更した場合、選択している全ユーザーの表示・職務経歴書に反映する

## 6. 非機能要件

### 6.1. 可用性

- 無料提供の期間は SLA を設けない。OCI 基盤（infra-oci リポジトリ管理の単一環境）が停止した場合、
  本サービスの全機能が利用できなくなることを許容する
- 障害時の復旧目標は以下のとおりとする

| 項目 | 目標値 |
| ---- | ------ |
| RPO（目標復旧時点） | 24 時間 |
| RTO（目標復旧時間） | 運営者が障害を検知してから 24 時間 |

- 有料機能の提供開始時に、可用性の目標を見直す

### 6.2. 性能

| 項目 | 目標値 |
| ---- | ------ |
| 公開ポートフォリオのページ読み込み | 3 秒以内 |
| スキル実績管理の画面操作の応答 | 3 秒以内 |
| 職務経歴書 PDF の生成 | 10 秒以内 |
| 登録ユーザー数 | 1,000 名 |
| 同時に操作するユーザー数（ログインして登録・PDF 生成を行うユーザー） | 20 名 |
| 外部ライブラリ（公開ポートフォリオ） | 最小限（Font Awesome、Google Fonts のみ） |

### 6.3. セキュリティ

- ユーザーは自分のデータのみを参照・変更でき、他のユーザーのデータには到達できない。
  この分離は、全ての参照・登録・変更・削除の操作について自動テストで検証する
- 本サービスはユーザーのパスワードを保持しない。認証は外部アカウント（Google・GitHub）に委ねる
- 通信は全て HTTPS で暗号化する
- 公開ポートフォリオは、ユーザーが公開を選んだ場合のみ第三者が閲覧できる。案件・会社・職務経歴書データ・
  職務経歴書 PDF は、所有するユーザー本人のみが参照できる
- 運営者は、障害対応・問い合わせ対応・規約違反の調査に必要な場合を除き、ユーザーの職務経歴書データを
  参照しない。この旨をプライバシーポリシーに明記する
- 個人情報の取扱いは個人情報保護法に従い、取得する情報・利用目的・保存期間・削除方法を
  プライバシーポリシーで示す
- アップロードできるファイルは画像に限り、種類・サイズを制限する
- 機械的な大量登録・大量アクセスを制限する
- リポジトリは public を維持する。Secret scanning、Push protection、
  Dependabot security updates を有効化し、機密情報のコミットを事前に遮断する
- ユーザーのデータ（運営者のデータを含む）は GitHub にアップロードしない。テストデータ・初期データにも
  実データを含めない

### 6.4. バックアップ・リストア

- 実績 DB とアップロードされた画像を日次でバックアップし、7 日分を保持する
- バックアップからのリストアは、6.1 節の RTO 内に完了できる手順を整備する
- ポートフォリオアプリのソースは GitHub リポジトリの履歴で管理する

### 6.5. 運用・保守

- ポートフォリオアプリの停止・エラーの多発を検知し、運営者へ通知する
- ポートフォリオアプリの本番デプロイは GitHub Actions による CI/CD で自動化する。
  Pull Request 作成時にテスト・Lint を実行し、`main` マージ後に本番環境へ自動デプロイする
- CI/CD から OCI ホストへの接続は、ファイアウォール（セキュリティ・リスト）を変更せず、
  OCI Bastion の Managed SSH Session 経由で行う
- アプリケーションのログには、ユーザーの職務経歴書データ・メールアドレス等の個人情報を出力しない
- 問い合わせへの対応は運営者 1 名で行う前提とし、回答期限は設けない

### 6.6. コスト

- 無料提供の期間は、infra-oci リポジトリが管理する既存の OCI 基盤（無料枠）と既存のドメインを用い、
  本サービスのために新たな恒常的費用を発生させない
- 外部アカウント認証（Google・GitHub）・Google フォームは無料の範囲内で利用する

### 6.7. 移植性・保守性

- 公開ポートフォリオの表示部分はフレームワーク非依存の Vanilla 構成とし、特定のビルドツールへの依存を持たない
- 表示データはポートフォリオアプリから取得し、生成元の実装に依存しない形式（JSON）でやり取りする

## 7. 制約・前提条件

### 7.1. 採用が決定済みの技術

- HTML5
- CSS3（Vanilla CSS）
- JavaScript（Vanilla、ES6+）
- OCI（ポートフォリオアプリ・実績 DB のホスト先。基盤自体は infra-oci リポジトリが管理する）

### 7.2. その他の前提

- 本リポジトリは public で公開する
- 本サービスは運営者 1 名（個人）で開発・運営する
- 利用者は日本国内の日本語話者を想定する
- 実績 DB は infra-oci リポジトリが管理する OCI 基盤上に配置し、本リポジトリでは管理しない
