# 要件定義書 - Portfolio サイト / スキル実績管理

## 1. プロジェクト概要

### 1.1. 目的

- 転職・案件獲得のためのアピール用ポートフォリオサイトを提供する
- 保有スキル・保有資格・実績を一覧できる形で公開する
- 案件ごとの使用実績（期間・使用スキル）を蓄積し、経験年数を自動で算出する。ポートフォリオサイトと
  職務経歴書の双方へ同一の値を供給し、手入力による二重管理をなくす
- スキル・資格・実績の登録内容を、手作業の反映作業を挟まずポートフォリオサイトの表示へ反映する

### 1.2. 背景

| 項目 | 内容 |
| ---- | ---- |
| プロジェクト名 | Portfolio サイト / スキル実績管理 |
| 対象サイト | <https://technohonesty.com/portfolio>（移行前は <https://seiya-nakagawa.github.io/Portfolio/>） |
| ホスティング | OCI 基盤（infra-oci リポジトリ管理） |

- 旧サイトは Bootstrap 4.5 + jQuery 依存の汎用テンプレートで構成され、デザインの差別化・パフォーマンス・保守性に課題があった
- リニューアルの過程でダークモード/ライトモード切替、日本語/英語の多言語対応、サイト内お問い合わせフォームを一時的に実装したが、
  「個人が月1回程度更新する」という運用実態に対して過剰であったため、現行実装では撤去済みである
- 経験年数をポートフォリオサイトの表示データと職務経歴書マスタの2箇所で別々に手入力しており、
  スキル項目・経験年数のいずれも両者の内容が一致していない
- 月次単位での実績登録は、月をまたいで作業内容を思い出しながら入力する必要があり、登録の手間から
  更新が滞りやすい
- 職務経歴書の「使用期間」は初めて使用した年からの経過年数で算出しており、実際に使用した期間を表していない
- ポートフォリオサイトの表示データを JavaScript のソースコード内に直接記述しており、
  データとコードが分離されていない
- スキル実績管理（旧: Google スプレッドシート + GAS）で登録した内容をポートフォリオサイトへ反映するには、
  出力した JSON をダウンロードし、リポジトリへ手作業で配置して PR を作成する必要があり、
  反映の手間から更新が滞りやすい。資格・実績（Certifications・Works）も同様に JSON ファイルの
  手作業編集で管理しており、同じ手間が発生していた
- ポートフォリオサイト（フロントエンド）を GitHub Pages、スキル実績管理を OCI 基盤とホスティング先を
  分ける構成も検討したが、個人のポートフォリオサイトに高可用性は求めておらず、分離のメリットが
  ないと判断し、両者を OCI 基盤へ統合した

### 1.3. 方針

- ポートフォリオサイト（フロントエンド）・スキル実績管理（登録・API 提供）は、いずれも OCI 基盤上に
  新設する単一のウェブアプリケーション（以下、ポートフォリオアプリ）で実現する。GitHub Pages での
  ホスティング、Google スプレッドシート・Google Apps Script（GAS）は用いない
- ポートフォリオアプリは、スキル・案件・使用実績・資格・実績を蓄積するデータベース（以下、実績 DB）を
  読み書きし、ポートフォリオサイトの表示・職務経歴書用データの出力に用いる
- ポートフォリオサイトの表示データは、ポートフォリオアプリが同一オリジンから動的に返す。
  表示データを JSON ファイルとしてリポジトリへコミットする運用は廃止する
- スキル実績管理は本人のみが利用するシングルユーザー構成とする
- 経験年数の入力口を案件単位の使用実績登録に一本化し、ポートフォリオ・職務経歴書の双方へ供給する。
  案件は開始年月・終了年月（継続中の場合は未設定）と、使用したスキル項目を保持する
- 直近案件（継続中、または最も新しく終了した案件）の使用スキルは、月1回程度更新する運用とし、
  案件の区切りを待たずに実績を反映できるようにする
- 資格（Certifications）・実績（Works）もポートフォリオアプリの登録機能で管理し、手作業での JSON 編集は廃止する
- 職務経歴書の文章部分は従来どおりローカルの Markdown マスタで管理し、スキル実績管理では扱わない
- ポートフォリオサイトの表示部分（HTML/CSS/JavaScript）は、ビルドプロセス・外部フレームワークへの
  依存を持たない Vanilla 構成を維持する
- 表示言語は日本語に固定する（多言語対応は行わない）
- 配色・見た目はダークモード基調に固定する（テーマ切替機能は持たない）

## 2. 対象範囲

### 2.1. スコープ内

ポートフォリオサイト。

- Hero / About / Skills / Certifications / Works / Contact の各セクション表示
- 表示データ（スキル・資格・実績）をポートフォリオアプリから取得して描画する
- レスポンシブ対応（モバイル / タブレット / デスクトップ）

スキル実績管理（ポートフォリオアプリ）。

- OCI 基盤上へのアプリケーション新設（インフラ自体の構築は infra-oci リポジトリの責務とし、
  本プロジェクトはアプリケーション自体を対象とする）
- 本人限定のアクセス制御（登録・変更操作）
- 案件単位の使用実績（期間・使用スキル）の登録
- スキル項目の登録・変更
- 資格（Certifications）・実績（Works）の登録・変更
- 経験年数の自動算出
- 職務経歴書の `■テクニカルスキル` 表および `■開発経歴` の期間の出力

### 2.2. スコープ外

- OCI 基盤自体の新規構築・運用（infra-oci リポジトリの責務とする）
- 本人以外への提供（マルチユーザー化）
- 職務経歴書の文章部分（職務概要・自己PR・業務内容・会社情報等）の管理
- 職務経歴書 PDF の生成（ローカルのビルドツールで実施する）
- サイト内でのお問い合わせフォーム処理（Google フォームへ誘導するのみとする）
- 多言語表示、テーマ（ダーク / ライト）切替
- ポートフォリオサイトの高可用性の確保（6.1 節参照）

### 2.3. 現行機能との差分

| 項目 | 現行 | 変更後 |
| ---- | ---- | ------ |
| ホスティング | GitHub Pages | OCI 基盤（infra-oci リポジトリ管理）に統合 |
| 表示データの保持・提供 | リポジトリ内 JSON ファイルを `fetch` で読み込む | ポートフォリオアプリが動的に返す |
| スキルデータの更新反映 | JSON を出力しリポジトリへ手作業配置・PR | ポートフォリオアプリへの登録が即時反映される |
| 資格・実績データの更新 | JSON ファイルを手作業編集 | ポートフォリオアプリの登録画面で更新する |
| スキル実績管理の実現方式 | Google スプレッドシート + GAS ウェブアプリ | OCI 基盤上のウェブアプリ + データベース |
| 職務経歴書の使用期間 | 初使用年からの経過年数 | 案件単位の使用実績から算出したユニーク月数の積み上げ |
| 案件単位の使用実績 | 管理していない | 実績 DB に蓄積する |

## 3. 用語定義

| 用語 | 定義 |
| ---- | ---- |
| スキル項目 | 経験年数の管理単位となる技術・製品。種類（カテゴリ）・名称・習熟度レベルを持つ |
| 案件 | 業務の単位。開始年月・終了年月（継続中の場合は未設定）と、使用したスキル項目を保持する |
| 使用実績 | ある案件であるスキル項目を使用したという記録 |
| ユニーク月数 | 案件の開始年月から終了年月（継続中の場合は出力時点の年月）までを年月に展開し、スキル項目ごとに重複を除いて数えた年月の件数 |
| 経験年数 | ユニーク月数を N年Mヶ月 に換算した値 |
| ポートフォリオアプリ | ポートフォリオサイトの表示・スキル実績管理を兼ねる、OCI 基盤上のウェブアプリケーション |
| 実績 DB | ポートフォリオアプリが読み書きするデータベース。OCI 基盤（infra-oci リポジトリ管理）上に配置する |
| 職務経歴書マスタ | 職務経歴書の内容を記述したローカル管理の Markdown ファイル |
| 直近案件 | 終了年月が未設定（継続中）の案件。存在しない場合は、終了年月が最も新しい案件 |

### 4.1. ポートフォリオサイト

| About | プロフィール情報表示、生年月日からの年齢自動計算。表示内容は管理画面から変更できる | 高 |
| Skills | カテゴリ別のスキルバー表示（技術名・経験年数・経験年数に基づく星 5 段階） | 高 |
| Certifications | 取得資格の一覧表示 | 中 |
| Works | 実績カードの一覧表示（GitHub リポジトリ等へのリンク） | 高 |
| Contact | Google フォームへのリンク、GitHub プロフィールへのリンク | 中 |
| 表示データの読み込み | ポートフォリオアプリから表示データを取得して各セクションを描画する | 高 |
| 表示データ取得失敗時の扱い | 取得に失敗した場合、該当セクションに読み込み失敗を示す文言を表示し、他セクションの描画は継続する | 高 |

| 機能 | 説明 | 優先度 |
| ---- | ---- | ------ |

| 案件実績登録 | 案件の開始年月・終了年月（継続中の場合は未設定）と、使用したスキル項目をチェックボックスで登録する。文章の入力は行わない | 高 |
| 直近案件の初期表示 | 登録画面の初期状態として、直近案件の登録内容（期間・使用スキル）を表示する | 高 |
| スキル項目の登録 | スキル項目を追加し、種類・習熟度レベルを設定する | 高 |
| 資格の登録 | 資格名・取得日・発行団体を登録・変更・削除する | 中 |
| 実績の登録 | 実績タイトル・説明・使用技術タグ・リンク等を登録・変更・削除する | 中 |
| About の変更 | 自己紹介文・生年月日・職業・学歴・居住地・趣味・GitHub URL を変更する | 中 |
| 経験年数の算出 | 案件単位の使用実績から算出したユニーク月数から経験年数を算出する | 高 |
| ポートフォリオ用データ提供 | ポートフォリオサイトの表示に必要なスキル・資格・実績・About データを返す | 高 |
| 職務経歴書用データ出力 | `■テクニカルスキル` 表と `■開発経歴` の案件期間を Markdown 形式で出力する | 高 |

## 5. 管理対象データ

| 情報 | 保持場所 | 保持する内容 |
| ---- | -------- | ------------ |
| スキル項目 | 実績 DB | 種類（カテゴリ）、名称、習熟度レベル |
| 案件 | 実績 DB | 案件の識別名、開始年月、終了年月（継続中の場合は未設定）、使用したスキル項目 |
| 資格 | 実績 DB | 資格名、取得日、発行団体 |
| 実績 | 実績 DB | タイトル、説明、使用技術タグ、リンク |
| About | 実績 DB | 自己紹介文、生年月日、職業、学歴、居住地、趣味、GitHub URL |

### 5.1. データに関する業務ルール

- 使用実績の登録単位は案件とする
- 同一期間に複数の案件を並行登録できる（本業と副業を並行する場合を想定する）
- 経験年数は、案件の開始年月〜終了年月（継続中の場合は出力時点の年月）を年月に展開したうえでの
  ユニーク月数の積み上げで算出し、N年Mヶ月 の形式で表示する。同一年月に複数の案件で同一の
  スキル項目を使用した場合も 1ヶ月として数える
- 案件の期間（開始年月・終了年月）は案件自体が保持する
- 登録画面の初期値は直近案件の登録内容（期間・使用スキル）とする。案件が1件も登録されていない
  場合は未選択とする
- 直近案件の使用スキルは、区切り（終了年月の確定）を待たずに月1回程度更新してよい
- 会社名・業務内容・体制・文章表現は実績 DB では管理せず、職務経歴書マスタで管理する
- ポートフォリオサイトのスキル・資格・実績データおよび職務経歴書の `■テクニカルスキル` 表は
  実績 DB の内容を正とし、手作業で編集しない
- ポートフォリオ向けに提供するデータには案件に関する情報を含めない。公開対象はスキル項目・経験年数・
  習熟度・資格・実績に限る
- 職務経歴書の実データは、個人情報および NDA 相当の案件情報を含むため、本リポジトリでは一切管理しない。
  ローカル環境で完結させる運用とする（詳細は
  [基本設計書 8章](../02.design/DESIGN.md#8-職務経歴書の管理方式)を参照）

## 6. 非機能要件

### 6.1. 可用性

- ポートフォリオサイトは個人のアピール用サイトであり、高可用性を要求しない。独自の SLA 目標は設けない
- ポートフォリオサイト・スキル実績管理のいずれも OCI 基盤（infra-oci リポジトリ管理の単一環境）上の
  ポートフォリオアプリ・実績 DB に依存する。基盤が停止した場合、ポートフォリオサイトの表示・
  スキル実績管理のいずれも利用できなくなることを許容する
- 可用性目標は、個人開発基盤（infra-oci）の可用性方針に準ずる

### 6.2. 性能

| 項目 | 目標値 |
| ---- | ------ |
| ポートフォリオサイトのページ読み込み | 3 秒以内 |
| スキル実績管理の画面操作の応答 | 3 秒以内 |
| 同時利用者数（ポートフォリオサイト閲覧） | 想定しない上限を設けない |
| 同時利用者数（スキル実績管理の登録操作） | 1 名 |
| 外部ライブラリ（ポートフォリオサイト） | 最小限（Font Awesome、Google Fonts のみ） |

### 6.3. セキュリティ

- スキル実績管理の登録・変更・削除操作は本人のみが行えるものとし、第三者に許可しない
- スキル・資格・実績の閲覧はポートフォリオサイトの表示に必要なため公開データとして提供する。
  案件情報は本人のみが参照できるものとし、公開データには含めない
- リポジトリは public を維持する。Secret scanning、Push protection、
  Dependabot security updates を有効化し、機密情報のコミットを事前に遮断する
- 個人情報・NDA 相当の案件情報を含む職務経歴書の実データは GitHub にアップロードしない
- 職務経歴書の作業ディレクトリは本リポジトリ内のパス（`skillsheet/`）に配置するが、
  `.gitignore` で除外し GitHub には一切アップロードしない
- `tools/skillsheet-builder/` で公開するビルドスクリプト・テンプレートには、ダミーデータのみを同梱する

### 6.4. バックアップ・リストア

- 実績 DB のバックアップ方式は infra-oci リポジトリのバックアップ方針に準ずる
- ポートフォリオアプリ・ポートフォリオサイトのソースは GitHub リポジトリの履歴で管理する

### 6.5. 運用・保守

- 直近案件の使用スキル更新頻度は月 1 回を想定する
- ポートフォリオサイトの更新頻度は月 1 回程度を想定する
- ポートフォリオアプリのデプロイ方針は infra-oci リポジトリの運用方針（CI/CD を設けず、
  作業端末から直接適用する）に準ずる

### 6.6. コスト

- ポートフォリオアプリ・実績 DB は、infra-oci リポジトリが管理する既存の OCI 基盤（無料枠）に相乗りし、
  本プロジェクトのために新たな恒常的費用を発生させない
- Google の無料枠（Google フォーム等）の範囲内で運用する

### 6.7. 移植性・保守性

- ポートフォリオサイトの表示部分はフレームワーク非依存の Vanilla 構成とし、特定のビルドツールへの依存を持たない
- 表示データはポートフォリオアプリから取得し、生成元の実装に依存しない形式（JSON）でやり取りする

## 7. 制約・前提条件

### 7.1. 採用が決定済みの技術

- HTML5
- CSS3（Vanilla CSS）
- JavaScript（Vanilla、ES6+）
- OCI（ポートフォリオアプリ・実績 DB のホスト先。基盤自体は infra-oci リポジトリが管理する）

### 7.2. その他の前提

- 本リポジトリは public で公開する
- スキル実績管理の利用者は本人 1 名とする
- 実績 DB は infra-oci リポジトリが管理する OCI 基盤上に配置し、本リポジトリでは管理しない
- 職務経歴書の作業ディレクトリは本リポジトリのパス配下（`skillsheet/`）に配置する。
  実体は Google ドライブ上に置き、`.gitignore` で除外することで
  GitHub には一切アップロードされないようにする
