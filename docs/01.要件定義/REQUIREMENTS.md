# 要件定義書 - Portfolio サイト / スキル実績管理サービス

## 1. プロジェクト概要

### 1.1. 目的

- 転職・案件獲得のためのアピール用ポートフォリオサイトを提供する
- 保有スキル・保有資格・実績を一覧できる形で公開する
- 月ごとのスキル使用実績を蓄積し、経験年数を自動で算出する。ポートフォリオサイトと職務経歴書の双方へ
  同一の値を供給し、手入力による二重管理をなくす
- サイトとサービスを OCI 上の Kubernetes で自ら運用し、インフラ・開発スキルを提示する

### 1.2. 背景

| 項目 | 内容 |
| ---- | ---- |
| プロジェクト名 | Portfolio サイト / スキル実績管理サービス |
| 現行ホスティング | GitHub Pages |
| 移行先ホスティング | OCI（Oracle Cloud Infrastructure）上の Kubernetes |

- 旧サイトは Bootstrap 4.5 + jQuery 依存の汎用テンプレートで構成され、デザインの差別化・パフォーマンス・保守性に課題があった
- リニューアルの過程でダークモード/ライトモード切替、日本語/英語の多言語対応、サイト内お問い合わせフォームを一時的に実装したが、
  「個人が月1回程度更新する」という運用実態に対して過剰であったため、現行実装では撤去済みである
- 経験年数をポートフォリオサイトの表示データと職務経歴書マスタの2箇所で別々に手入力しており、
  スキル項目・経験年数のいずれも両者の内容が一致していない
- 職務経歴書の「使用期間」は初めて使用した年からの経過年数で算出しており、実際に使用した期間を表していない

### 1.3. 方針

- ホスティングを GitHub Pages から OCI 上の Kubernetes へ移行する
- 静的サイトに加えてスキル実績管理サービスを併設し、両者をホスト名で分離して公開する
- スキル実績管理サービスは本人のみが利用するシングルユーザー構成とする
- 経験年数の入力口を月次のスキル使用実績登録に一本化し、ポートフォリオ・職務経歴書の双方へ出力する
- 職務経歴書の文章部分は従来どおりローカルの Markdown マスタで管理し、本サービスでは扱わない
- 静的サイトは HTML/CSS/Vanilla JavaScript 構成を維持し、ビルドプロセス・外部フレームワークへの依存を持たない
- 表示言語は日本語に固定する（多言語対応は行わない）
- 配色・見た目はダークモード基調に固定する（テーマ切替機能は持たない）

## 2. 対象範囲

### 2.1. スコープ内

ポートフォリオサイト。

- Hero / About / Skills / Certifications / Works / Contact の各セクション表示
- 資格・実績データのメンテナンス
- レスポンシブ対応（モバイル / タブレット / デスクトップ）

スキル実績管理サービス。

- 本人認証
- 月次のスキル使用実績の登録
- 案件の登録および月次実績への紐づけ
- スキル項目の登録・変更
- 経験年数の自動算出
- ポートフォリオサイトのスキル表示用データの出力
- 職務経歴書の `■テクニカルスキル` 表および `■開発経歴` の期間の出力

ホスティング。

- 静的サイトおよびサービスの OCI Kubernetes 上での稼働
- 独自ドメインでの公開と TLS 終端

### 2.2. スコープ外

- 本人以外への提供（一般公開のマルチユーザーサービス化）
- 職務経歴書の文章部分（職務概要・自己PR・業務内容・会社情報等）の管理
- 職務経歴書 PDF の生成（ローカルのビルドツールで実施する）
- サイト内でのお問い合わせフォーム処理（Google フォームへ誘導するのみとする）
- 多言語表示、テーマ（ダーク / ライト）切替

### 2.3. 現行機能との差分

| 項目 | 現行 | 移行後 |
| ---- | ---- | ------ |
| ホスティング | GitHub Pages | OCI 上の Kubernetes |
| スキル表示データ | ソース内のデータファイルを直接編集 | スキル実績管理サービスの出力を反映 |
| 職務経歴書の使用期間 | 初使用年からの経過年数 | 月次使用実績のユニーク月数の積み上げ |
| サーバーサイド処理 | 持たない | スキル実績管理サービスとして持つ |

## 3. 用語定義

| 用語 | 定義 |
| ---- | ---- |
| スキル項目 | 経験年数の管理単位となる技術・製品。種類（カテゴリ）・名称・習熟度レベルを持つ |
| 使用実績 | ある年月にあるスキル項目を使用したという記録 |
| ユニーク月数 | 使用実績が存在する年月を重複を除いて数えた件数 |
| 経験年数 | ユニーク月数を N年Mヶ月 に換算した値 |
| 案件 | 業務の単位。月次の使用実績に紐づけて登録する |
| 職務経歴書マスタ | 職務経歴書の内容を記述したローカル管理の Markdown ファイル |
| 直近の登録済み年月 | 対象年月より前で、使用実績が登録されている年月のうち最も新しいもの |

## 4. 機能要件

### 4.1. ポートフォリオサイト

| 機能 | 説明 | 優先度 |
| ---- | ---- | ------ |
| ナビゲーション | アンカーリンクによるスムーズスクロール、モバイル用ハンバーガーメニュー | 高 |
| Hero | タイピングアニメーションによる肩書き表示 | 中 |
| About | プロフィール情報表示、生年月日からの年齢自動計算 | 高 |
| Skills | カテゴリ別のスキルバー表示（技術名・経験年数・習熟度） | 高 |
| Certifications | 取得資格の一覧表示 | 中 |
| Works | 実績カードの一覧表示（GitHub リポジトリ等へのリンク） | 高 |
| Contact | Google フォームへのリンク、GitHub プロフィールへのリンク | 中 |

### 4.2. スキル実績管理サービス

| 機能 | 説明 | 優先度 |
| ---- | ---- | ------ |
| 認証 | 本人のみがログインできる。未認証の状態では画面を表示しない | 高 |
| 月次実績登録 | 対象年月を選び、スキル項目のチェックボックスで使用実績を登録する。文章の入力は行わない | 高 |
| 前月内容の初期表示 | 登録画面の初期状態として、直近の登録済み年月のチェック状態を再現する | 高 |
| 案件の月次選択 | 対象年月に従事した案件を選択する。複数選択でき、初期値は直近の登録済み年月と同一とする | 高 |
| 案件の登録 | 案件を新規に登録する | 高 |
| スキル項目の登録 | スキル項目を追加し、種類・習熟度レベルを設定する | 高 |
| 経験年数の算出 | 使用実績のユニーク月数から経験年数を算出する | 高 |
| ポートフォリオ用データ出力 | ポートフォリオサイトのスキル表示に取り込める形式で出力する | 高 |
| 職務経歴書用データ出力 | `■テクニカルスキル` 表と `■開発経歴` の案件期間を Markdown 形式で出力する | 高 |
| 未登録月の提示 | 登録漏れを防ぐため、使用実績が未登録の年月を画面上に提示する | 低 |

## 5. 管理対象データ

| 情報 | 保持する内容 |
| ---- | ------------ |
| スキル項目 | 種類（カテゴリ）、名称、習熟度レベル |
| 案件 | 案件の識別名 |
| 月次使用実績 | 年月、案件、使用したスキル項目 |
| ポートフォリオ掲載情報 | 資格、実績（サービスでは管理せず、静的サイト側で保持する） |

### 5.1. データに関する業務ルール

- 使用実績の登録単位は年月（1ヶ月）とする
- 同一年月に複数の案件を登録できる（本業と副業を並行する場合を想定する）
- 経験年数はユニーク月数の積み上げで算出し、N年Mヶ月 の形式で表示する。
  同一年月に複数の案件で同一のスキル項目を使用した場合も 1ヶ月として数える
- 案件の期間は、その案件が登録されている年月の最小値と最大値から導出する。案件側で期間を保持しない
- 登録画面の初期値は直近の登録済み年月の内容とする。登録済みの年月が存在しない場合は未選択とする
- 使用実績が登録されていない年月は、実績なしとして扱う
- 会社名・業務内容・体制・文章表現は本サービスでは管理せず、職務経歴書マスタで管理する
- ポートフォリオサイトのスキル表示データおよび職務経歴書の `■テクニカルスキル` 表は
  本サービスの出力を正とし、手作業で編集しない
- 職務経歴書の実データは、個人情報および NDA 相当の案件情報を含むため、本リポジトリでは一切管理しない。
  ローカル環境で完結させる運用とする（詳細は
  [基本設計書 8章](../02.設計/DESIGN.md#8-職務経歴書の管理方式)を参照）

## 6. 非機能要件

### 6.1. 可用性

- ベストエフォートとし、SLA 目標・RTO / RPO の目標値は設けない
- 単一ノード構成のため、インスタンス障害時はインフラ側の再構築によって復旧する

### 6.2. 性能

| 項目 | 目標値 |
| ---- | ------ |
| ポートフォリオサイトのページ読み込み | 3 秒以内 |
| スキル実績管理サービスの画面操作の応答 | 3 秒以内 |
| 同時利用者数 | 1 名 |
| 外部ライブラリ（静的サイト） | 最小限（Font Awesome、Google Fonts のみ） |

### 6.3. セキュリティ

- スキル実績管理サービスは認証を必須とし、未認証で参照できる画面を持たない
- 通信は HTTPS に限定する
- 案件情報は本人のみが参照できるものとし、ポートフォリオサイトの公開画面には表示しない
- データベース接続情報は OCI Vault を真実源とし、コード・マニフェスト・環境変数定義に平文で保持しない
- リポジトリは public を維持する。Secret scanning、Push protection、
  Dependabot security updates を有効化し、機密情報のコミットを事前に遮断する
- 個人情報・NDA 相当の案件情報を含む職務経歴書の実データは GitHub にアップロードしない
- 職務経歴書の作業ディレクトリは本リポジトリ内のパス（`skillsheet/`）に配置するが、
  `.gitignore` で除外し GitHub には一切アップロードしない
- `tools/skillsheet-builder/` で公開するビルドスクリプト・テンプレートには、ダミーデータのみを同梱する

### 6.4. バックアップ・リストア

- スキル使用実績のデータベースは日次でバックアップを取得する
- 静的サイトのソース・Kubernetes マニフェストは GitHub リポジトリの履歴で管理する

### 6.5. 運用・保守

- 使用実績の登録頻度は月 1 回を想定する
- ポートフォリオサイトの更新頻度は月 1 回程度を想定する
- `main` ブランチへのマージを契機に、静的サイトおよびサービスが公開環境へ反映されること

### 6.6. コスト

- OCI Always Free 枠の範囲内で運用する
- 独自ドメインの取得・維持費用を除き、恒常的な費用を発生させない

### 6.7. 移植性・保守性

- 静的サイトはフレームワーク非依存の Vanilla 構成とし、特定のビルドツールへの依存を持たない
- スキル実績管理サービスはコンテナとして構成し、Kubernetes 上で動作させる

## 7. 制約・前提条件

### 7.1. 採用が決定済みの技術

- HTML5
- CSS3（Vanilla CSS）
- JavaScript（Vanilla、ES6+）
- OCI（Always Free 枠）
- Kubernetes
- MySQL
- OCI Vault（機密情報の管理）

### 7.2. その他の前提

- 本リポジトリは public で公開する
- インフラ層（Compute インスタンス、Kubernetes クラスタ、MySQL、OCI Vault）は infra-oci リポジトリの
  管理範囲とし、本リポジトリでは Kubernetes マニフェストとアプリケーションを管理する
- データベースは Kubernetes 上には配置せず、infra-oci が共通管理するホスト OS 上の MySQL を利用する
- 独自ドメインを取得し、ポートフォリオサイトとスキル実績管理サービスをホスト名で分離する
- スキル実績管理サービスの利用者は本人 1 名とする
- 職務経歴書の作業ディレクトリは本リポジトリのパス配下（`skillsheet/`）に配置する。
  実体は Google ドライブ上に置き、`.gitignore` で除外することで
  GitHub には一切アップロードされないようにする
